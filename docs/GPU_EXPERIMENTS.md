# GPU 电脑的实际重建记录

以下摘要来自本项目已完成的本机实验。硬件为 RTX 4060 Laptop 8GB、i9-14900HX，WSL 可用物理内存约 15.5 GiB。SfM/MVS 使用 CPU 4 线程；3DGS 使用 Windows Brush 的 GPU；Fast3R 使用 WSL CUDA。原图、点云、逐次日志和完整报告留在忽略的 `data/`、`outputs/`，没有随 GitHub 发布。没有使用几何真值评价精度。

## Kitchen 200 张

输入为 200 张 994×738 RGB，OPENCV 共享相机、全量两两匹配、最大边长 1200；从照片重新估计 SfM，没有导入发布位姿。

| 阶段 | 结果 | 阶段耗时 |
|---|---|---:|
| COLMAP 3.7 SfM | 183/200 张注册到单模型，25,754 个点，平均点重投影误差 0.537 px | 1266.0 秒 |
| OpenMVS 2.3 稠密点云 | 3,260,161 个点，164 张深度图参与融合 | 325.9 秒 |
| Brush 0.3 3DGS | 5000 步，211,467 个高斯，160 张训练、23 张留出 | 125.0 秒 |

MVS、3DGS 复用同一 SfM，阶段时间不包含前置 SfM；两项后续任务曾同时运行，时间之和不作为实际续跑墙钟时间。3DGS 保存的图像事后评估为平均 PSNR 21.70 dB、SSIM 0.7968，参考 JPEG 与渲染 PNG 没有另行缩放。该评估使用已知位姿的留出视角，SfM 位姿和初始点使用全部注册照片，指标不代表几何精度，也不是 Brush 控制台原始指标。

本机完整报告：`outputs/kitchen200-comparison/README.md`。

## Fast3R 容量与质量

独立环境：Python 3.11、PyTorch 2.5.1+cu124、BF16；官方源码固定为 `33104d4b5b8df43795ecded236194958bbdac572`，模型为 `jedyang97/Fast3R_ViT_Large_512`。不编译 cuROPE，使用 `pytorch_auto`，输出头逐视图处理。

输入来自 kitchen 300 张子集的另一套嵌套名单，与上面的 kitchen 200 张名单不同。每视图保留置信度不低于 50 分位的点，导出上限 300,000；没有把多个局部坐标系直接拼接。

| 预处理尺寸 | 视图数 | 结果 | 前向秒 | PyTorch 峰值分配 GiB |
|---|---:|---|---:|---:|
| 512 | 32 | 两次成功 | 5.61～6.00 | 5.42 |
| 512 | 48 | 一次干净复测成功 | 10.28 | 6.36 |
| 512 | 56 | 一次成功 | 13.28 | 6.82 |
| 512 | 64 | 两次成功，耗时波动 | 17.18～63.43 | 7.28 |
| 512 | 80、128 | 各自 180 秒预算内未完成，已中断 | — | — |
| 224 | 200 | 一次成功 | 14.01 | 6.66 |

512 档实际为 512×368，224 为中心裁剪的 224×224。计时为前向时间，不含模型加载、预处理、导出；显存为 PyTorch 分配峰值。Windows 同期全局计数器显示专用显存接近用尽、共享 GPU 内存最高约 1.34 GiB，支持显存压力与降速有关，但没有单独量化换页成本。没有捕获 CUDA OOM，也没有确定硬容量上限。首个 48 张运行受残留 worker 影响，已排除，表中使用清理后的复测。

建议先用 2～4 张验证部署，日常试验先取 32～48 张。224/200 虽运行成功，房间点云散乱、重影明显；512/32 可辨认局部物体，但仍有孔洞和漂浮点。固定同一批 32 张比较 224/512 与绝对置信度过滤后，过滤减少杂点，同时只剩少数视图贡献点，未恢复完整场景。绝对阈值实验未改变产品默认导出规则，置信度分数不代表准确率。

本机完整报告：`outputs/fast3r-capacity-kitchen/README.md`、`outputs/fast3r-confidence-kitchen032/README.md`。安装与首轮命令见 [FAST3R.md](FAST3R.md)。

## Tanks and Temples / Train 301 张

输入为官方完整 301 张 1920×1080 RGB，SIMPLE_RADIAL 共享相机、顺序匹配（邻近数量 10）、最大边长 1200；MVS 只执行稠密点云，resolution-level=1、最多 5 个邻近视角、至少 2 个视角融合。没有导入发布位姿。

| 项目 | 结果 |
|---|---|
| SfM 注册 | 301/301，单一模型 |
| 稀疏点 / 平均点重投影误差 | 162,324 / 0.841 px |
| 稠密点 / 参与融合深度图 | 6,692,989 / 301 |
| SfM / MVS 额外耗时 | 1296.7 / 871.2 秒 |
| 路线总耗时 | 2168.4 秒，约 36 分 8 秒 |

目视可辨认机车整体、车身和轨道，MVS 的表面覆盖更连续；阴影、遮挡和细杆仍有缺失，背景有散点。该结果证明这组 301 张在所列配置下完成流程。Train 使用顺序匹配，kitchen 使用全量匹配，不能将耗时差异归因于图片数量，也不能据此宣称已找到容量上限。

本机完整报告：`outputs/t2-train301-sequential-first/README.md`。Train 没有取得适用公开几何真值，未报告几何精度或完整度。Barn 410 张、Meetingroom 371 张已下载校验，尚未重建；来源见 [TANKS_AND_TEMPLES.md](TANKS_AND_TEMPLES.md)。
