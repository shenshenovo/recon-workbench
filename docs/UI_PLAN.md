# 页面逻辑与测试扩展规划

界面采用“重建工作台、项目记录、实验对比”三页。三页前端与路由已实现，重建与持久化接口继续复用；数据扩展部分是下一阶段计划。

## 现状与目标

当前页面同时展示项目管理、上传、筛选、算法参数、运行状态、历史、模型、对比表和评估曲线。主要问题是用户执行一次重建需要跨多个长区块操作，点云查看不突出，当前任务与历史任务的状态容易混淆。

界面划分三个主页面：**重建工作台、项目记录、实验对比**。顶部保留简洁导航、当前项目与运行中任务入口；页面用工作区、步骤栏、表格和分栏组织内容。

## 1. 重建工作台

目标：完成一次从图片到结果的操作。

流程：选择项目 → 上传或复用输入 → 检测并保存筛选 → 设置路线 → 启动 → 查看结果。

- 原始照片使用“图片与筛选 / 重建设置 / 结果”三个步骤。步骤切换保留当前输入和设置，不重新上传。
- 已有 SfM / Brush 输入直接进入适用的重建设置；不要强行要求重复筛选。
- 图片步骤显示缩略图、勾选与问题筛选；详细分数和阈值按需展开。始终区分原始总数、当前勾选、已保存的实际输入数。
- 设置步骤展示 SfM/MVS/3DGS 的用途、基础参数与高级参数；不同时展开所有路线的字段。
- 执行时主区展示阶段与运行状态；没有可靠总进度的阶段不显示虚假的精确百分比。日志默认折叠，失败时突出原因和日志入口。
- 完成后主区以大尺寸点云为中心，工具栏提供稀疏/稠密切换、视角和点大小；旁边显示此次任务的输入数和结果信息。
- 当前普通点云使用 WebGL。3DGS 使用现有 Brush 查看入口，网格/纹理使用已有文件入口，界面不把它们伪装成普通点云。
- 模型下载和网页网格/高斯渲染为单独的后续功能，不以页面重构替代其实现。

## 2. 项目记录

目标：查找、管理并复用已有工作。

- 项目列表：名称、更新时间/记录时间、任务数量；创建与改名。
- 项目详情分“图片集 / 任务历史 / 模型记录”页签，只展示当前页签的内容。
- 图片集：缩略图、原始/已选数量、检测与确认状态，“用于重建”返回工作台对应输入。
- 任务历史：所有状态、路线、时间与耗时；按名称、状态、路线筛选。测试/演示数据与正式实验需要明确区分，具体字段方案待实施时确认。
- 任务详情展示保存参数、实际图片名单、阶段、错误与日志；“查看结果”打开工作台的该历史任务，不创建新任务。
- 模型记录按来源任务展示，避免纹理附件与完整模型混排而让用户误以为有很多独立模型。

## 3. 实验对比

目标：回答“在什么条件下，这次实验和另一次有什么差别”。

- 先选择场景/图片集，再选择路线与已完成实验，不默认将全部历史和短训练一起排名。
- 显示数据来源、实际输入名单指纹、分辨率、任务耗时范围与关键配置。
- 同一场景不同路线：可并列展示耗时、结果文件大小、输出类型与截图，不混用几何和渲染指标给总分。
- SfM 展示注册率、重投影误差；MVS 可展示点数/面数，但这些不替代几何真值精度。
- 3DGS 同评估条件下展示 PSNR/SSIM、训练步数和曲线；评估分组不同则明确提示，不作统一质量排名。
- 对比固定少量已选实验，提供表格/曲线与 JSON/CSV 导出。原图和渲染对照需要准确对应视角。

## 导航与状态

- 每页有独立 URL，支持刷新和前进/后退；不能只依靠滚动到锚点模拟分页面。
- 推荐路径：`/reconstruct`、`/projects`、`/experiments`；任务结果通过稳定 `task_id` 定位。
- 当前项目在页面间保持；“用于重建”和“查看历史结果”区分新建模式和只读结果模式。
- 离开工作台不停止后台计算；全局任务入口可回到运行任务。记录页和对比页不重复加载点云、图片质量表和全部日志。
- 未保存的勾选或参数，切换时保留草稿或明确提示，避免静默丢失。
- 默认路径不预填本机 ETH3D 目录；首次访问有清晰的上传入口。

## 测试与数据扩展

现有 65 项自动化检查主要验证文件安全、模块调用、状态、上传、筛选、持久化、页面路由及相机参数传递，不等价于 65 次真实场景重建，也不证明质量检测准确率或重建精度。

建议先覆盖 3～4 个有明确目的的场景，而不是下载多个完整数据集：

| 场景 | 验证目的 | 需要记录 |
| --- | --- | --- |
| 室外建筑 | 复用现有基线，验证三条路线和新界面 | 版本、输入名单、配置、注册率、耗时、产物 |
| 室内/少纹理 | 检查困难输入与失败反馈 | 特征不足、注册失败、可视覆盖及原因 |
| 小物体/桌面 | 检查近距离、遮挡和环绕拍摄 | 可见区域、孔洞、背景和纹理 |
| 自采照片 | 验证普通用户上传与质量筛选 | 原始照片、人工标注、检测提示、最终选择 |

正式实验分为：正常场景复现、异常流程、质量筛选验证、控制变量对比。

- 正常场景：固定输入、工具版本与参数，保留可复现命令和输出。
- 异常流程：损坏图片、视角不足、取消、失败、服务重启和筛选后改图。
- 质量检查：合成退化用于验证响应；另取人工标注样本，分析误报与漏报。不要将告警数量当准确率。
- 筛选前后：固定正常视角，在额外加入退化/重复图的条件下比较，检查是否损失有效覆盖，不预设筛选一定提升结果。
- 控制变量：先选一个因素（如最大边长、3DGS 步数），保持其他条件一致，区分端到端耗时与复用阶段耗时。计时实验避免同时运行多个重建。
- 几何精度：只有取得可用真值、完成对齐并定义评估协议后才报告精度/完整度；没有时明确缺失。

页面验收还需覆盖三页跳转、刷新/后退、跨页后台运行、草稿保存、历史结果打开和对比条件提示。

## 实施顺序

1. 确认三页职责、导航和状态流转。
2. 重做前端结构与样式，复用现有重建、质量和持久化接口；按页面拆分脚本，移除通过 DOM 搬动区块的组织方式。
3. 完成现有数据上的回归和页面验收。
4. 根据测试目标核对公开数据的格式、下载规模、许可和真值，再选择小场景扩展正式实验。

## 本次页面验收

在独立临时项目与浏览器中验证，测试数据不混入用户正式数据库：

- 三页是独立 URL；记录页没有加载点云画布或质量筛选表。
- 已选 8 张中取消一张，离开再返回，恢复未保存的 7 张草稿；重新确认 8 张后可进入设置。
- 使用 8 张真实照片启动 SfM，立即切到项目记录，再从顶部运行入口返回；后台任务正常完成，8 张注册成功，点云可加载。
- 失败任务可以查看错误，历史完成任务可在工作台打开结果。
- 图片集页签与模型归集正常；对比页支持选择、条件提示与 JSON/CSV 报告导出。
- 430 像素宽的工作台和对比页无整体横向溢出；宽表格在各自区域滚动。

刷新和草稿恢复主要使用当前浏览器标签的 sessionStorage；它不是跨设备草稿同步。已保存的筛选、任务、模型仍使用数据库。
